# Migrating from v0.7 to v0.8

## Overview

v0.8.0 reconciles the PAdES, CAdES, and XAdES signing APIs into one shared contract:
a strongly typed baseline profile (`AdesBaselineProfile`), consistent result semantics
(`ISigningResult`), an explicit external-signing request (`IExternalSigner`), and a single
HTTP provider model (`IHttpClientProvider`). This is a **breaking release**: the legacy
capability methods and options objects were removed rather than deprecated.

The core patterns are unchanged — `static entry point → immutable fluent builder →
async terminal method` — but several names and configuration styles changed.

## PAdES: entry points and results

| v0.7 | v0.8 |
|---|---|
| `SimpleSigner.Document(pdf)` | `PadesSigner.Document(pdf)` |
| `SimpleSigner.Document(pdf, logger)` | `PadesSigner.Document(pdf).WithLogger(logger)` |
| `SimpleSigner.DocumentAsync(path)` | `PadesSigner.DocumentAsync(path)` |
| `SignerBuilder` | `PadesSignerBuilder` |
| `PdfSigningResult.Pdf` | `PadesSigningResult.SignedArtifact` |
| `PdfSigningResult.DssEmbedded` | `PadesSigningResult.HasLongTermValidationMaterial` |
| `result.Warnings` (`IReadOnlyList<string>`) | `result.Warnings` (`IReadOnlyList<SigningWarning>`, `.Code` + `.Message`) |

`SignerBuilderBrasilExtensions.WithAdvancedSignature()` now extends `PadesSignerBuilder`
(same call syntax).

## Level configuration: one complete profile

The ETSI baseline levels are cumulative outcomes, so the level and all of its
dependencies are now requested together:

```csharp
using SimpleSign.Core.Signing;

var timestamp = new TimestampOptions(new Uri("https://tsa.example.com"));

// B-B: no profile call needed (default) or AdesBaselineProfile.Basic()
// B-T:
builder.WithLevel(AdesBaselineProfile.Timestamped(timestamp));

// B-LT:
builder.WithLevel(AdesBaselineProfile.LongTerm(timestamp, new LongTermValidationOptions()));

// B-LTA (null archive options reuse the signature TSA):
builder.WithLevel(AdesBaselineProfile.Archive(timestamp, new LongTermValidationOptions()));

// B-LTA with a dedicated archival TSA:
builder.WithLevel(AdesBaselineProfile.Archive(
    timestamp, new LongTermValidationOptions(),
    new ArchiveTimestampOptions(new Uri("https://archive-tsa.example.com"))));
```

| v0.7 | v0.8 |
|---|---|
| `.WithTimestamp(url)` | `.WithLevel(AdesBaselineProfile.Timestamped(new TimestampOptions(new Uri(url))))` |
| `.WithTimestamp(url).WithLtv()` | `.WithLevel(AdesBaselineProfile.LongTerm(new TimestampOptions(new Uri(url)), new LongTermValidationOptions()))` |
| `.WithTimestamp(url).WithLtv().WithArchivalTimestamp()` | `.WithLevel(AdesBaselineProfile.Archive(new TimestampOptions(new Uri(url)), new LongTermValidationOptions()))` |
| `.WithTimestamp(url).WithLtv().WithArchivalTimestamp(other)` | `AdesBaselineProfile.Archive(..., new ArchiveTimestampOptions(new Uri(other)))` |
| `CadesSignerBuilder.WithLevel(CadesLevel.X)` | `.WithLevel(AdesBaselineProfile.Basic()/Timestamped/LongTerm/Archive)` |
| `XadesSignerBuilder.WithLevel(XadesLevel.X)` | `.WithLevel(AdesBaselineProfile.*)` |
| `CadesSigner.SignAsync(data, cert, options, …)` | `CadesSigner.Document(data).WithCertificate(cert).WithLevel(profile).SignAsync()` |
| `XadesSigner.SignAsync(xml, cert, options, …)` | `XadesSigner.Document(xml).WithCertificate(cert).WithLevel(profile).SignAsync()` |
| `CadesSigningOptions` / `XadesSigningOptions` | Removed — use the builder |

`WithLevel` replaces the complete profile atomically; call order no longer affects the
requested level.

## Strict level fulfillment

The requested level is now a **postcondition**:

- Requesting B-LT/B-LTA without collectible certificate/revocation material throws
  `SigningException` (reason `SigningErrorReason.LevelNotAchievable`) instead of silently
  producing a lower-level artifact.
- Opt-in downgrades are explicit:
  `AdesBaselineProfile.LongTerm(ts, ltv, failureBehavior: SigningLevelFailureBehavior.ReturnLowerLevel)`
  with `SignWithDetailsAsync()`, which reports `RequestedLevel`, `AchievedLevel`, and a
  `SigningWarning` with code `SigningWarningCode.LevelDowngraded`.
- The byte-only `SignAsync()` rejects best-effort profiles
  (`SigningErrorReason.DowngradeRequiresDetailedResult`); use `SignWithDetailsAsync()`.

Result flags describe the produced artifact: basic PAdES signatures now report
`HasLongTermValidationMaterial == false`, and CAdES/XAdES no longer report LTV merely
because `Level >= LongTerm` was requested.

## HTTP configuration

| v0.7 | v0.8 |
|---|---|
| `.WithHttpClient(client)` (PAdES: default/revocation + TSA fallback; CAdES/XAdES: TSA) | `.WithHttpClientProvider(new SingleClientProvider(client))` (builder-wide fallback) |
| `.WithTimestamp(url, client)` | `new TimestampOptions(new Uri(url), new SingleClientProvider(client))` |
| `.WithRevocationHttpClient(client)` | `new LongTermValidationOptions(new SingleClientProvider(client))` |
| `.WithHttpClientProvider(provider)` | unchanged (builder-wide fallback) |

Provider precedence: scoped option provider → builder-wide provider → default.
Providers are resolved lazily at signing time and are never disposed by the signer.

## External signing

`Func<byte[], Task<byte[]>>` overloads were removed. Implement `IExternalSigner`:

```csharp
public sealed class MyHsmSigner : IExternalSigner
{
    public async ValueTask<ReadOnlyMemory<byte>> SignAsync(
        ExternalSigningRequest request, CancellationToken cancellationToken)
    {
        // request.DataToSign, request.HashAlgorithm, request.SignatureAlgorithmOid,
        // request.PayloadKind, request.OperationId
        return await hsm.SignAsync(request.DataToSign, request.HashAlgorithm);
    }
}

builder.WithExternalSigner(cert, new MyHsmSigner(), chain); // chain overload optional
```

Legacy delegates can be wrapped with `new FuncExternalSigner(async data => …)`.
The signature algorithm OID is resolved at signing time; use `.WithSignatureAlgorithm(oid)`
for explicit control. All three formats now support chain-capable external signing
overloads.

## Errors

Invalid completed signing configuration and signing failures now throw
`SigningException` (with a stable `SigningErrorReason`) across all formats; the
`InvalidOperationException`/`ArgumentException` split of v0.7 is gone.
`OperationCanceledException` always propagates unchanged.

## What did not change

- `DeferredSigner` / `DeferredSignerBuilder` (two-phase PAdES signing) — unchanged.
- `BatchSigner` / `BatchSignerBuilder` public API — unchanged (internally migrated).
- Validation APIs and their level enums (`CadesLevel`, `XadesLevel`) — unchanged.
- PAdES-specific operations (`WithAppearance`, `WithFieldName`, `AsCertification`,
  `WithPdfAPreservation`, `WithSubFilter`, `WithLegacyCms`, `WithMetadata`,
  `WithCountryExtension`), XAdES packaging (`WithForm`, `WithDataUri`, `WithSignerRoles`,
  `WithDataObjectFormat`), and CAdES `WithContentType` — unchanged.
