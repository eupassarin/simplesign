# Migrating from v0.9 to v0.10

## Overview

v0.10.0 replaces the boolean PAdES validation verdict with the three ETSI
indications and turns `SimpleSign.HtmlToPdf` into a full CSS layout engine.
Only the validation change is source-breaking; the HtmlToPdf changes are
additive, with a few rendering behaviors documented below.

## PAdES validation: `IsValid` → `Indication`

`SignatureValidationResult.IsValid` has been removed. The single overall result
is now `SignatureValidationResult.Indication`, a `SignatureIndication`:

| Indication | Meaning |
| --- | --- |
| `Valid` | The validation policy was satisfied. |
| `Invalid` | A conclusive integrity, cryptographic-signature or revocation failure was found. |
| `Indeterminate` | Integrity and the signature are fine, but there is not enough evidence (untrusted or unbuildable chain, unknown revocation status). |

Before:

```csharp
if (result.IsValid) { /* accept */ }
```

After:

```csharp
switch (result.Indication)
{
    case SignatureIndication.Valid:
        // accept
        break;
    case SignatureIndication.Indeterminate:
        // missing evidence: ask for revocation data, a trust anchor, or review manually
        break;
    case SignatureIndication.Invalid:
        // reject
        break;
}
```

Code that only needs a yes/no answer should treat **only** `Valid` as accepted:
`result.Indication == SignatureIndication.Valid`. Do not map `Indeterminate` to
valid — it is the case where the old boolean was ambiguous.

The detailed flags (`IsIntegrityValid`, `IsSignatureValid`,
`IsCertificateChainValid`, `IsNotRevoked`, `RevocationSource`, `Errors`,
`Warnings`) are unchanged.

CAdES and XAdES results (`CadesSignatureValidator`, `XadesValidationResult`)
keep their `IsValid` property.

### CLI and HostSigner JSON

`simplesign validate --json` replaces the boolean `valid` field of each
signature with the string field `indication` (`"Valid"`, `"Invalid"` or
`"Indeterminate"`), and the HostSigner validation response replaces `isValid`
the same way. Update scripts that filtered on `valid == true`, for example
with `jq`:

```bash
simplesign validate signed.pdf --json | jq '.signatures[] | select(.indication == "Valid")'
```

Console output of `validate` and `validate-dir` shows `VALID`, `INVALID` or
`INDETERMINATE` for each signature, and the summary counts the three groups.

## HtmlToPdf behavior changes

The public API only gained members (`WithFont`, `WithFontFile`,
`WithBaseDirectory`, `WithResourceLoader`, `WithPdfA`, `WithLanguage`,
`FontVariant`, new `ComputedStyle` properties). Output changes you may notice:

- **Colors with alpha** (`rgba()`, `#RRGGBBAA`, `hsla()`) are drawn with PDF
  transparency instead of being composited over white. `PdfColor.Alpha` exposes
  the opacity.
- **`CssParser.ParseLength`** encodes percentages as values at or below
  −100000 (−100000 − p) instead of −p, so negative lengths such as
  `margin-left: -10px` keep their meaning. If you call it directly, test for a
  percentage with `value <= -50000` and decode it as `-value - 100000`.
- **Embedded fonts are shaped** with their OpenType tables (kerning, ligatures),
  so text set in a registered font can be slightly narrower than before.
- **Hard hyphens** (`well-known`) are line-break opportunities.
- **`overflow: hidden`** clips descendants, and a box with a fixed `height`
  keeps exactly that height.
- The root or `<body>` background now covers the whole page, like browsers.
- A forced page break after the last element no longer adds a blank page.

See [HTML to PDF](../articles/html-to-pdf.md) for the full CSS support matrix.
