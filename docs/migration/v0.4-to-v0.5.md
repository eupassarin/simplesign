# Migration Guide: v0.4 → v0.5

## Breaking Changes

### `SignerBuilder.WithTimestamp(url, httpClient)` scope narrowed

The injected `HttpClient` now applies only to TSA calls (signature timestamp + archival DocTimeStamp), not to revocation (OCSP/CRL/AIA). Use the new `WithHttpClient(HttpClient)` for the default/revocation client.

```diff
 var builder = SimpleSigner.Document(pdf)
     .WithCertificate(cert)
-    .WithTimestamp(tsaUrl, tsaClient);  // previously leaked to revocation
+    .WithTimestamp(tsaUrl, tsaClient)
+    .WithHttpClient(revocationClient);  // explicit revocation client
```

### `BatchSignerBuilder` immutable

`With*` methods now return new instances instead of `this`. Code relying on reference identity after `With*` calls will break.

```diff
 var builder = BatchSigner.Create(cert);
- builder.WithTimestamp(url);           // mutated original — no longer works
+ var builder2 = builder.WithTimestamp(url);  // returns new instance
```

### `SignatureValidationResult` namespace changed

Moved from `SimpleSign.PAdES.Validation` to `SimpleSign.Core.Validation`. Add `using SimpleSign.Core.Validation;` to existing code.

```diff
- using SimpleSign.PAdES.Validation;
+ using SimpleSign.Core.Validation;
```

### `ISignatureManifestProvider` removed

This interface was dead code and has been removed. Manifest construction uses `SignatureMetadata` directly without interface indirection. Implementations of `ISignatureManifestProvider` will no longer compile.

### `IChainValidationProvider` async

`Validate` changed to `ValidateAsync`, fixing sync-over-async deadlock. Update implementations:

```diff
- public ValidationChainResult Validate(X509Chain chain, ...)
+ public async Task<ValidationChainResult> ValidateAsync(X509Chain chain, ..., CancellationToken ct)
```

## New Features in v0.5

- **`SimpleSign.CAdES`** — standalone CMS/PKCS#7 signing library (ETSI EN 319 122) with fluent builder and CLI commands
- **RSA-PSS** certificate support: `RSASSA-PSS-params` emitted per RFC 4055 §3.1
- **Algorithm inference** — hash automatically derived from PSS cert params and RSA key size (NIST SP 800-57)
- **Chain overloads on `WithExternalSigner`** — HSM/callers can supply pre-fetched intermediate certificate chain
- **`CountryExtension`** plug-in system — register country-specific trust anchors and chain validators
- **`HttpClientFactoryProvider`** — built-in `IHttpClientFactory` adapter
- **Per-operation HTTP client slots** — TSA (signature + archival) and revocation now use independent `HttpClient` instances
- **SHA-3 hash** support (.NET 9+)
- **EdDSA** external signer + verification
- **QR code** on visible signatures
- **DocMDP** certification enforcement
- **PDF/A-aware annotation flags** — Print + Locked for PDF/A-2+
- **LTV loop parallelisation** — `Parallel.ForEachAsync` with `ConcurrentDictionary`
- **AIA issuer-subject validation**
- **PDF/A detection for compressed XMP**

## Upgrade Steps

1. Update `SimpleSign` package to v0.5.x
2. Add `using SimpleSign.Core.Validation;` where `SignatureValidationResult` is referenced
3. Add `using SimpleSign.CAdES;` for CAdES signing/validation
4. If using `IChainValidationProvider`, update `Validate` → `ValidateAsync` with `CancellationToken` parameter
5. If using `ISignatureManifestProvider`, migrate to `SignatureMetadata` directly
6. If using `BatchSignerBuilder` with `.WithX()` mutations, capture return values
7. If using `.WithTimestamp(url, client)` and relying on the client for revocation, add `.WithHttpClient(client)`
