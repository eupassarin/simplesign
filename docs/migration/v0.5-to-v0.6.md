# Migration Guide: v0.5 → v0.6

## Breaking Changes

### `DeferredSignerBuilder.WithSignatureAlgorithmOid()` renamed to `WithSignatureAlgorithm()`

The method was renamed for consistency with `SignerBuilder.WithSignatureAlgorithm()` and `CadesSignerBuilder.WithSignatureAlgorithm()`.

```diff
 var builder = new DeferredSignerBuilder(pdfBytes, cert)
-    .WithSignatureAlgorithmOid(Oids.EcdsaSha384);
+    .WithSignatureAlgorithm(Oids.EcdsaSha384);
```

### Signature algorithm OID now preserved in auto-detect `WithExternalSigner`

Both `SignerBuilder` and `CadesSignerBuilder` now respect a previously-set `.WithSignatureAlgorithm(oid)` when calling the chain-less `WithExternalSigner` overloads. Previously the user-specified OID was silently discarded. This is technically a behavior change: if you called `.WithSignatureAlgorithm(oid)` followed by `.WithExternalSigner(cert, signer)` and relied on the OID being discarded, the OID will now be used.

```diff
 var builder = SimpleSigner.Document(pdfBytes)
     .WithSignatureAlgorithm(Oids.EcdsaSha384)  // was ignored, now respected
     .WithExternalSigner(cert, externalSigner);
```

## New Features in v0.6

### `CadesSignerBuilder` — fluent CAdES API

CAdES signing now has a fluent builder API matching the PAdES pattern:

```csharp
using SimpleSign.CAdES;

byte[] cms = await CadesSigner
    .Document(data)
    .WithCertificate(cert)
    .WithTimestamp("http://timestamp.digicert.com")
    .WithHashAlgorithm(HashAlgorithmName.SHA384)
    .WithSignatureAlgorithm(Oids.RsaSha512)
    .SignAsync();
```

The existing `CadesSigner.SignAsync()` static methods still work and now delegate to the builder internally.

### `CadesSigningResult` — sign and inspect

`CadesSignerBuilder.SignWithDetailsAsync()` returns a `CadesSigningResult` with diagnostic metadata:

```csharp
var result = await CadesSigner
    .Document(data)
    .WithCertificate(cert)
    .WithTimestamp(tsaUrl)
    .SignWithDetailsAsync();

Console.WriteLine($"Timestamp: {result.TimestampApplied}");
Console.WriteLine($"LTV: {result.LtvDataEmbedded}");
foreach (var warning in result.Warnings)
    Console.WriteLine($"Warning: {warning}");
```

### `IChainValidationProvider` with CancellationToken

A new overload of `ValidateAsync` accepts `CancellationToken`. The interface provides a default implementation that delegates to the parameterless overload, so existing implementations are not broken. Implementors can optionally add cancellation support:

```diff
 public class MyChainValidator : IChainValidationProvider
 {
     public Task<ChainValidationResult> ValidateAsync(
         X509Certificate2 certificate,
-        IReadOnlyList<X509Certificate2>? chain = null);
+        IReadOnlyList<X509Certificate2>? chain = null,
+        CancellationToken cancellationToken = default);
 }
```

## Fixes

### VRI `/SHA256` key removed from DSS dictionary

The non-standard `/SHA256` key inserted into every VRI entry has been removed. It was not defined in ISO 32000-2 §12.8.4.4 Table 250 and caused ETSI Signature Conformance Checker schema validation failures. VRI dictionaries now only contain the spec-defined keys: `/Type`, `/Cert`, `/CRL`, `/OCSP`, `/TS`, and the SHA-1 key.

### `DetectSignatureAlgorithmOid` consolidated

Three duplicate copies of the signature OID detection logic (in `SignerBuilder`, `DeferredSigner`, and `CadesSigner`) have been merged into a single shared implementation in `CryptoUtility.DetectSignatureAlgorithmOid`. No API changes required.

## Upgrade Steps

1. Update packages to v0.6.x
2. Rename `WithSignatureAlgorithmOid()` → `WithSignatureAlgorithm()` on `DeferredSignerBuilder` calls
3. If implementing `IChainValidationProvider`, optionally add `CancellationToken` support
4. Migrate CAdES signing code to `CadesSignerBuilder` if you want the fluent API (optional — old static API still works)
